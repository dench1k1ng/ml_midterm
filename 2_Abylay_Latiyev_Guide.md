## Что реализовано

`credit_pipeline.py`: исходные данные → построчные преобразования `DomainCleaner`
→ обучаемый `ColumnTransformer` → модель в едином sklearn `Pipeline`.

- Разбиение 5 400 / 1 350, stratified 80/20, `random_state=42`. Исходный
  `artifacts/participant2/split_indices.csv` сохранён без изменений.
- Числа: медианы; денежные признаки — `log1p`; масштабирование для линейной модели.
- Стаж: упорядоченная кодировка, медиана и индикатор отсутствующего/неизвестного значения.
  `10+ years -> 10` обозначает нижнюю границу категории, а не точный стаж.
- Категории: one-hot и объединение редких уровней; неизвестные категории не ломают transform.
- Общий индикатор отсутствия дохода/скоринга, индикаторы пропусков просрочек и стажа.
- Сумма `99999999`: гипотеза заглушки, заменяется пропуском; отдельно сохраняется флаг.
- Скоринг >850: сравниваются /10, пропуск и исходное значение.
- Все обучаемые шаги повторно обучаются **внутри каждого CV-фолда**. Test-target
  исключён через `usecols` при чтении; все 750 строк test и их порядок сохранены.

Отрицательных/бесконечных чисел в исходном аудите не найдено. Произвольная очистка
будущих некорректных числовых значений вне схемы этого датасета не заявляется.
Ни выбросы, ни строки test не удаляются.

## Откуда взялось «10» и почему параметры теперь обоснованы

В переписке не указан конкретный параметр прошлого проекта. Поэтому в отчёте
различены три случая:

1. **C=10** — один из проверенных вариантов, а не выбранная наугад константа.
2. **Деление скоринга на 10** — гипотеза масштаба: 6060–7510 переходят в 606–751,
   все аномальные значения кратны десяти. Это не подтверждение семантики данных.
   В CV проверены также замена пропуском и отсутствие исправления.
3. **Стаж 10+** — категория с известной нижней границей.

Перебраны 120 комбинаций на одинаковых 5 стратифицированных фолдах обучающей части:

| Параметр | Варианты |
|---|---|
| C | 0.01, 0.1, 1, 10, 100 |
| class_weight | None, balanced |
| min_frequency | 1, 10, 20, 50 |
| score_policy | divide, missing, raw |

Критерий выбора — средний F1 класса 1. Порог предсказания фиксирован: 0.5.
Победитель: **C=0.1, balanced, min_frequency=50, score_policy=missing**;
CV F1 = **0.5588**. Все результаты, включая значения по каждому фолду,
сохранены в `artifacts/participant2/parameter_search_cv.csv`.

Лучший CV-результат после перебора оптимистичен; это не независимая оценка.
Validation не используется для пересмотра выбранных параметров.

## Ограничения, которые нужно понимать на защите

- Все исходные строки со скорингом >850 имеют класс 1, с суммой 99999999 — класс 0.
  До подтверждения времени и способа записи этих данных результаты с флагами
  экспериментальные. Удаление флагов не доказывает отсутствия утечки: исходные
  аномалии могут сохраняться через пропуски и коррелирующие признаки.
- Денис исследовал целевую переменную всего исходного train, включая будущие
  validation-строки. Обучаемые преобразования разделены корректно, но validation
  нельзя называть полностью слепой независимой оценкой после такого EDA.
- Значение класса 1 («дефолт» или «одобрение») в задании формально не определено.
  В отчёте используются буквальные классы 0 и 1.
- Медиана для пропущенных просрочек не означает, что просрочек не было;
  индикатор позволяет модели отдельно учитывать отсутствие сведений.

## Передача участнику 3

Исходный API `cp.load_data()`, `cp.load_split()`, `cp.build_preprocessor()` сохранён.
Полные параметры победителя записаны в `baseline_summary.json`; префиксы ключей
соответствуют sklearn Pipeline. Пример восстановления выбранного pipeline:

```python
import json
from sklearn.pipeline import Pipeline
from sklearn.linear_model import LogisticRegression
import credit_pipeline as cp

summary = json.load(open('artifacts/participant2/baseline_summary.json'))
model = Pipeline([
    ('preprocess', cp.build_preprocessor()),
    ('model', LogisticRegression(max_iter=2000, random_state=cp.RANDOM_STATE)),
]).set_params(**summary['parameter_search']['best_params'])
X, y, X_test = cp.load_data()
tr, va = cp.load_split()
model.fit(X.loc[tr], y.loc[tr])
```

`baseline_validation_predictions.csv` — прежняя модель;
`tuned_validation_predictions.csv` — выбранная по CV и её вариант без флагов.
Все сравнения проводятся на сохранённом разбиении. Параметры и пороги новых моделей
лучше выбирать на training-only CV/OOF, после чего сравнить validation-метрики.
Test-метки загружает только участник 3 для финальной оценки замороженной модели.

Пять автоматических проверок покрывают неизменность разбиения, обучающие медианы,
отсутствие обучения при transform, неизвестные категории и стаж, варианты обработки
скоринга, сохранение строк и порядка test, совместимость предобработки с деревьями.
