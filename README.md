# House Price Prediction — командный проект

Проект посвящён прогнозированию цены дома (`SalePrice`) по его характеристикам. Основная работа выполняется в Jupyter Notebook [`main.ipynb`](main.ipynb).

Срок сдачи: **8 октября, 23:59**. Кроме кода команда должна подготовить короткую презентацию и защитить проект во время занятия.

## Что требуется по заданию

В проекте необходимо показать и объяснить:

1. очистку и предварительную обработку данных;
2. обучение и валидацию моделей;
3. сравнение моделей по метрикам регрессии;
4. EDA-графики, результаты и основные выводы;
5. финальную презентацию без лишних теоретических историй.

Для регрессии используются MAE, RMSE и R². Обычная classification accuracy здесь неприменима.

## Данные

- `train.csv` — 1 314 строк для анализа, обучения и cross-validation;
- `test.csv` — 146 строк для единственной финальной проверки;
- `data_description.txt` — описание признаков;
- `SalePrice` — целевая переменная;
- `Id` — идентификатор строки, а не полезный признак модели.

В `test.csv` уже присутствует настоящий `SalePrice`. Его нельзя использовать для обучения, выбора модели или настройки гиперпараметров. До финального теста человек 2 работает только с `train.csv`.

## Общая схема работы команды

```text
Человек 1: данные и EDA
          ↓ handoff
Человек 2: preprocessing, Pipeline и модели
          ↓ модели + CV-таблица
Человек 3: аудит, выбор модели, финальный test и презентация
```

Работа разделена по этапам, но на защите каждый участник должен понимать всю цепочку:

```text
таблица → X/y → пропуски → encoding → обучение → prediction → ошибка → cross-validation
```

## Человек 1 — данные и EDA

### Главная ответственность

Человек 1 должен подготовить понятное и проверяемое описание данных для команды. Он не выбирает лучшую модель и не вычисляет финальные test-метрики.

### Что он должен сделать

1. Проверить размеры train/test, названия колонок и типы данных.
2. Найти дубликаты, повторяющиеся ID и пересечение train/test.
3. Проверить пропуски и разделить их на две группы:
   - отсутствие объекта: нет бассейна, гаража, камина и так далее;
   - действительно неизвестное значение, которое требует imputation.
4. Определить признаки, которые хранятся числом, но являются категориями. В этом наборе таким признаком является `MSSubClass`.
5. Исследовать распределение `SalePrice` и возможную необходимость `log1p`-преобразования.
6. Построить полезные EDA-графики:
   - распределение цены;
   - количество пропусков;
   - корреляции числовых признаков;
   - цена относительно `OverallQual` и `GrLivArea`;
   - медианная цена по `Neighborhood`.
7. Сформулировать выводы словами, не выдавая корреляцию за причинность.
8. Передать человеку 2 конкретные правила preprocessing.
9. Проверить воспроизводимость EDA и сохранение всех 146 тестовых строк.

### Что уже выполнено

Работа человека 1 находится в разделе 1 [`main.ipynb`](main.ipynb). Подготовлены:

- проверка целостности данных;
- анализ типов и 79 потенциальных признаков;
- таблица пропусков и правила их обработки;
- анализ распределения `SalePrice`;
- числовые корреляции;
- анализ качества, жилой площади и районов;
- пять PNG-графиков и четыре CSV-таблицы в [`eda_artifacts/`](eda_artifacts/);
- файл передачи [`EDA_HANDOFF.md`](EDA_HANDOFF.md);
- воспроизводимый запуск EDA в ноутбуке.

Проверенные результаты:

- дубликатов строк и ID нет;
- ID между train и test не пересекаются;
- медиана `SalePrice` равна `$162,950`;
- распределение цены имеет длинный правый хвост, skewness около `1.88`;
- наиболее сильные числовые связи с ценой показывают `OverallQual`, `GrLivArea`, `GarageCars`, `GarageArea`, `TotalBsmtSF` и `1stFlrSF`.

### Что человек 1 передаёт человеку 2

Человек 2 получает:

- исходные CSV без изменений;
- правила обработки из [`EDA_HANDOFF.md`](EDA_HANDOFF.md);
- названия смысловых групп пропусков;
- таблицы и графики из [`eda_artifacts/`](eda_artifacts/);
- требование исключить `Id` и `SalePrice` из матрицы признаков;
- требование выполнять imputation и encoding внутри `Pipeline`.

Готовый `cleaned_train.csv` намеренно не создаётся. Если заранее обработать весь набор, можно случайно передать информацию из validation-fold в обучение и получить data leakage.

## Человек 2 — preprocessing и модели

Человек 2 заполняет раздел 2 [`main.ipynb`](main.ipynb).

Его задачи:

1. Создать `X` и `y` только из `train.csv`.
2. Сохранить `Id` отдельно и убрать его из признаков.
3. Преобразовать `MSSubClass` в категорию.
4. Создать `ColumnTransformer` для числовых и категориальных признаков.
5. Выполнять imputation и one-hot encoding внутри `Pipeline`.
6. Добавить baseline, например `DummyRegressor`.
7. Обучить несколько понятных моделей, например Ridge, Random Forest и Gradient Boosting или Extra Trees.
8. Проверить все модели на одинаковых cross-validation folds.
9. Сформировать единую таблицу CV-метрик MAE, RMSE и R².
10. Передать человеку 3 рабочие pipeline, параметры и таблицу результатов.

Человек 2 не использует test-метрики для выбора модели.

## Человек 3 — финальная оценка и презентация

Человек 3 заполняет раздел 3 [`main.ipynb`](main.ipynb).

Его задачи:

1. Проверить Pipeline человека 2 на data leakage.
2. Убедиться, что все модели сравнивались на одинаковых folds.
3. Выбрать модель по результатам train/CV.
4. При необходимости настроить модель, используя только train и cross-validation.
5. Зафиксировать модель и обучить её на всём `train.csv`.
6. Только после этого один раз оценить модель на всех 146 строках `test.csv`.
7. Посчитать финальные MAE, RMSE и R².
8. Построить графики actual vs predicted и распределения ошибок.
9. Подготовить таблицу сравнения и итоговые выводы.
10. Собрать короткую презентацию и провести репетицию защиты.

### Что выполнено человеком 3

Раздел 3 `main.ipynb` содержит аудит preprocessing и CV-разбиений, выбор модели только по train/CV, обучение на полном train и финальную оценку всех 146 test-строк. Дополнительная настройка гиперпараметров не проводилась.

Результаты и ограничения описаны в [`FINAL_HANDOFF.md`](FINAL_HANDOFF.md). В [`final_artifacts/`](final_artifacts/) сохраняются:

- аудит пяти folds и всех pipeline;
- сравнение CV-моделей и зафиксированная конфигурация выбора;
- финальные MAE, RMSE, R² и прогнозы с исходными ID;
- actual vs predicted, распределение residual и residual vs predicted;
- краткая статистика ошибок.

Презентация PPTX передаётся отдельно и не хранится в репозитории. Повторный запуск ноутбука воспроизводит ту же зафиксированную процедуру оценки, без выбора или настройки модели по test.

## Локальный запуск

Установить зависимости:

```bash
python -m pip install -r requirements-test.txt
```

Запустить Jupyter:

```bash
jupyter lab main.ipynb
```

В ноутбуке выбрать **Restart Kernel and Run All Cells**.

Проверить, что ноутбук выполняется с нуля без ошибок:

```bash
jupyter nbconvert --to notebook --execute main.ipynb --output /tmp/main_check.ipynb
```

## Правила совместной работы

- Не изменять исходные `train.csv`, `test.csv` и `data_description.txt`.
- Перед началом работы перезапускать ноутбук с чистого kernel.
- Не редактировать одновременно одни и те же ячейки `main.ipynb`.
- За итоговую сборку ноутбука отвечает один назначенный участник.
- Не выбирать модель по результатам test.
- После каждого объединения запускать весь ноутбук с чистого kernel.
- Не писать в презентации результаты, которых нет в выполненном ноутбуке.
